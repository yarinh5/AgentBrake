# Private local service limits and external acceptance gates

- **Scope:** default installation remains one local tenant, synthetic PostgreSQL and local Git/mock PR. The v0.3 candidate adds an opt-in GitHub App disposable-repository adapter and HTTPS; see PRODUCTION_OPERATIONS.md. Its offline API contract tests are not real GitHub verification. No arbitrary SQL, paid inference or production deployment has been authorized for a named target.
- **Completion:** evidence/local-release.json is the exact-source local engineering gate. Milestone D external human security sign-off and T29 independent clean-machine installation remain open. Agent review is not human certification; market interviews/paid pilots are not fabricated.
- **Identity:** one-time owner bootstrap followed by managed password accounts, administrator-issued invitations/recovery, role changes, disable and revision-based session invalidation. Generated role keys are disabled after setup; legacy test compatibility retains key login. Software cannot prove two accounts belong to different physical people. Email is an unverified login identifier; no email is sent. If all administrators lose access there is no hidden authentication bypass. No SSO/OAuth/MFA or multi-tenant hosting. Stolen bearer retains its bounded scope until revoke/expiry; no theft detector. Reissue an identity after its one-hour token expires.
- **Isolation:** agent/control/protected/dashboard networks are internal. Docker29 requires a separate credential-free fixed TCP ingress on a regular network to publish only127.0.0.1. It forwards only to dashboard:3000 and has no request-selected destination or secrets. Host administrator/Docker daemon/kernel compromise and unrestricted host agents are outside the boundary.
- **Git:** local fixture has atomic ref/mock PR updates. The separate App adapter uses bounded paths/feature branches and draft PRs, pins repository/owner IDs and requires protected main and no repository workflows. GitHub multi-step writes are not atomic; partial failure is UNKNOWN. No merge/release/main/force/delete/workflow/issue writes. External organization webhooks require operator verification; the App is not granted admin permissions to inspect them.
- **DB:** fixed schema metadata, bounded SELECT and one-row status update. Reader is read-only; writer only executes a version-checked function owned by NOLOGIN role. Preview exposes id/status/version; CAS prevents stale overwrite. Adapter rejection after dispatch is zero effect, not zero upstream calls.
- **Transactions:** control reservation binds authority/quota/taint/action/audit atomically. Stop/revoke blocks new reservations, not an already reserved effect. No in-flight rollback. Lost response/crash becomes UNKNOWN; reconcile before any new request. Same request never blindly retries.
- **Evidence:** pending is not execution; adapter success is not independent target verification. Redacted filtered exports cannot reconstruct the original full hash chain independently. Host/bootstrap owner can rewrite storage/code. No WORM/external signing. UI polls every10seconds; no subsecond/SLA claim.
- **Retention:** terminal result payload default24hours, configurable1..8760, pruned at startup/hourly. Decisions/review/arguments/audit/replay tombstones persist until explicit installation reset. Monitor disk/export deliberately. Bounded encrypted cold backup/restore is implemented; require the matching service acceptance report. No HA or online point-in-time recovery. Application logs default10MiB×3; local OTLP JSON only, no remote collector.
- **Bounds:** workspace latest500actions; activity page100; export10000records. Limits are per-process; one Gateway per installation. No horizontal failover claim. Owner-run additive control migration002 has a checksum ledger; existing fixture data is preserved. Cold restore requires the exact pinned PostgreSQL image,256MiB/10000entries per volume and64MiB encrypted package. No arbitrary or major-version migration.
- **Content controls:** secret patterns and taint are bounded, not universal DLP, semantic injection detection or inter-agent flow tracking. Two legitimate placeholders were conservatively blocked in the26-task baseline. Expected approvals are separate from false blocks.
- **Codex:** official CLI0.169.0 with actual Qwen3:4b/Ollama0.40.16 local inference. One bounded model workflow, separate forced injection replay and deterministic26-task benchmark. Not statistical model reliability. Tested NVIDIA RTX2060 SUPER8GiB/64GiB host; CPU-only/fresh-machine model preparation unverified. Public caches retained, inference isolated.
- **Security checks:** pinned Semgrep OSS with8local rules and parser-error gate, CycloneDX SBOM and npm advisory scans. The candidate adds pinned offline Trivy image scanning; only its actual exact-build report counts, including unresolved findings. None is a pentest or external human review. Known fixture credentials are checked in artifacts; no universal secret detector claim.
- **History:** older A/B reports and failed C/D attempts remain. PASS applies only to its source hash/scope; final release gate supersedes older current-source claims. No Git commit exists.

External deployment, paid services, real-system access and material requirement changes still require explicit user approval.
