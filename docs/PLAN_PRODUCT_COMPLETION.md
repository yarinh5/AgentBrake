## Scope decisions

- KEEP the verified PEP, OPA policies, MCP transport, PG runtime roles/atomic reservations, Git fixture and React components. EXTEND approval/actor/evidence contracts. Migrate the UI into a separate Next.js process only after the underlying controls work.
- One local configured tenant per deployment is the MVP. Separate operator identities/roles and explicit tenant checks protect control endpoints. Enterprise multi-tenant hosting/SSO remain out of scope. Local operator credentials are generated by setup; no real accounts or email service are needed. The existing single-owner memory mode remains explicitly labeled a compatibility/developer fixture; the installable product uses team controls.
- The team workflow requires independent approvers, server-issued human ownership, CSRF-protected sessions and exact reviewed-action proof. Pending approval is not execution. A persisted nonce/fingerprint and atomic action reservation bind one successful execution attempt to one review; audit records include actual operator identity.
- Preview is an adapter-defined read, not an execution or generic SQL dry run. Git uses canonical diff/base; a bounded DB status update uses minimal before/after fields and a target-side version condition. Unknown preview/target changes fail closed. Preview observations are counted separately from execution attempts; denied invocations have no execution calls.
- Control API records approvals, while the separate Gateway executes via the same PEP. No dashboard process gets target/PDP credentials. Persistent local install uses named project-only volumes and versioned forward migrations; destructive reset must explicitly identify the disposable installation.
- GitHub App remains disabled without a user-supplied disposable repository; ship an explicit configuration template, not a PAT or an untested enabled connector. No live service is required to complete the local MVP.
- External human security sign-off, independent clean-machine installation and market interviews cannot be fabricated. Prepare a reproducible review/install package and record these external acceptance gates honestly; local engineering success is not production or business validation.

Research: OWASP [transaction authorization](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html) supports showing significant action data and final authorization at dispatch; [session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) distinguishes CSRF defense from SameSite cookies. [Next.js self-hosting](https://nextjs.org/docs/app/guides/self-hosting) and [Docker standalone packaging](https://docs.docker.com/guides/nextjs) inform the separate local dashboard runtime. Choices remain constrained to the actual installed SDK/runtime contracts.
