# ADR 0006: remove unused vulnerable image components

Status: locally verified on source993f7cbf1a3a56dcb421f88368efa67dbbcf37809d0d45b9cdf54e0ab80287c7; no production acceptance claim.

Cause: offline Trivy0.76.2 scan5cb5e4e7 reported164high/critical findings in the Debian/full-dependency runtime,49in dashboard,26in the PostgreSQL gosu Go runtime, and1in OPA's x/net0.60.0. The package-level npm audit alone did not cover image operating-system packages, bundled npm, or Go binaries in development dependencies. Full scanner output is retained; no global severity filter or ignore list was added.

New installations record `runtimeProfile: minimal-v1`. Existing manifests without that marker retain their original Node/PostgreSQL/OPA profile; product-local is not rebuilt or migrated implicitly by this task. Production Node uses a separately digest-pinned official Node22 Alpine image. Runtime keeps only production dependencies and the already-pinned tsx runtime loader. Vite/test/build dependencies, bundled npm/yarn/corepack, curl and psql are absent from the runtime image; Git remains necessary for the local fixture adapter. Health checks use Node. Dashboard build dependencies remain in the builder stage, outside its final image.

PostgreSQL retains the exact pinned official PostgreSQL18 base and database binaries. A small derived image removes `/usr/local/bin/gosu`, whose only role is switching from root: Compose already starts both databases as postgres with all capabilities dropped. Existing volume ownership initialization is separate. The derived tag includes the base digest and Dockerfile hash; backup/restore's existing image-match check therefore rejects a different recipe.

OPA uses unchanged checksum-pinned official v1.22.4 source, with only `golang.org/x/net` raised to the scanner's fixed0.62.0 version. Build uses pinned Go1.27.4, upstream static/opa_wasm build flags, module checksum verification and the HTML dependency's tests. The final image is scratch with the binary, certificates and license, uid1000. This is an AgentBrake security rebuild, not an upstream OPA release. Its recipe determines its image tag. Policy unit tests and the real policy HTTP/approval/failure/isolation paths must pass on this image before acceptance.

The intermediate hardened scan ad15f490 found zero high/critical issues, with one remaining Medium zlib finding in each Alpine Node image. The [upstream zlib change log](https://github.com/madler/zlib/blob/develop/ChangeLog) identifies the infback9 pointer-arithmetic fix for CVE-2026-4738. A disposable package-index query confirmed Alpine3.24 offers zlib1.4-r0; the new runtime/dashboard stages explicitly install that version. Actual rebuilt-image scanning must confirm the disposition.

Restore resolves the authenticated installation profile through the same function as normal startup, before destination creation. Legacy profiles retain their old digest; unknown profiles and changed recipe identities are rejected. The initial comparison against only the base digest was a verified recovery regression, repaired with fail-first actual-orchestration tests and scoped rereview.

Alternatives: suppress all unfixed findings (rejected; hides risk), remove capabilities alone (insufficient evidence of elimination), change application security architecture (unrelated), upgrade the installed user's data/services implicitly (rejected). The additional maintenance cost is documented: retire the dependency rebuild when a verified upstream image includes the fix, then rerun exact-source tests/scans.
