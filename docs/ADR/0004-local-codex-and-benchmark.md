# ADR 0004 — Actual Codex with local inference and a bounded workflow benchmark

Accepted for Milestone B local verification, 2026-11-16. The user forbids real-system access and paid services. Use the official Codex CLI with real local Qwen3 4B inference through Ollama's Responses endpoint. A scripted model stub would not satisfy the actual-Codex gate; hosted inference would violate the authorized scope. This choice proves the CLI/MCP/Gateway path, not the behavior of a hosted OpenAI model or statistical agent reliability.

Public dependency preparation is separate from runtime. `infra/local/codex.lock.json` pins Codex/npm metadata, the Ollama image digest, reviewed registry manifest and local provenance wrapper, plus every model blob. Verification rehashes every cached blob. The Codex executable SHA-256 and container image IDs are recorded in each run. Downloads use no task or user account credentials. Public build/download traffic is allowed only in preparation; model inference uses internal Docker networks with no host-published ports.

Codex gets a clean ephemeral home and only its bounded task bearer. It shares the agent network with Gateway and an inference-only network with Ollama. The model has a read-only weights mount and no task credentials. Neither receives the Docker socket, host workspace, administrator, target, database or policy secrets. Rootless users, dropped capabilities, read-only roots and resource limits remain enforced. The GPU/runtime and host administrator are trusted; this is not protection against a compromised host or kernel.

Two read tools are explicitly preapproved in the disposable Codex MCP configuration, matching the operator's read-only task. The Gateway still independently checks scope, expiry, quota and OPA. Codex shell/web tools are disabled. Other client-side approvals are not interpreted as Gateway enforcement evidence. The actual README includes a synthetic hostile instruction; a separate forced request with the same read-only credential proves the Gateway denial even when the model itself ignores that instruction. The two successful reads are also replayed exactly with a test client and checked against independent snapshots/counters.

The benchmark labels 26 legitimate intents before execution and retains benign password/API-key placeholders as legitimate tasks. It compares direct fixture execution with Gateway execution. It records policy false denials, expected approvals and infrastructure/adapter failures separately; unknown/PDP failures cannot qualify as policy false blocks. Every baseline must succeed and no non-policy failure is allowed; completion must be at least 90% relative to baseline. Trusted operator approval is excluded from autonomous-agent claims.

Scope limits: one curated corpus, sequential direct/Gateway execution on the same disposable fixture, distinct branch names and explicit per-step state checks. A baseline status update can precede an update to the same status with a new version; this is not a randomized fresh-state experiment. There is no population false-positive estimate, confidence interval or comparison of LLM quality. Authorization timing is the recorded Gateway pre-dispatch span, excluding target execution; it is not an isolated OPA microbenchmark or commercial SLA. The actual Codex workflow is separate from these deterministic test-client tasks.

Teardown includes every Compose profile and verifies zero project containers, networks and volumes. Exact known synthetic credentials are scanned in generated evidence; the fixture operator separately scans all credentials it creates. These scans do not establish universal DLP. No user `.env`, existing data, global Codex config or registry credentials are used.
