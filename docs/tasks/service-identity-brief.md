## Exact API contract for UI/root integration

Existing /api/login supports strict {key:string} in compatibility/pre-bootstrap mode and strict {email:string,password:string} for managed accounts. Returns existing session shape actor/csrfToken/teamMode with optional authMode ('key'|'account'). Existing /api/session includes optional authMode; existing /api/logout works.

GET /api/setup -> {managed:boolean,initialized:boolean} unauthenticated (no names/emails/secrets).
POST /api/setup -> {key,name,email,password} strict, generated admin credential only; atomically creates first administrator then returns normal login session. Repeat409; invalid key401; no authority from body. Optional workspaceName max80 if helpful must document before UI work.
POST /api/invitations/accept -> {token,name,password}, consumes invitation and returns normal session. Email/role bound to stored invite; not accepted from body. Invitation link itself is generated by UI from returned token in URL fragment (no server query/log token).
POST /api/password/reset -> {token,password}, consumes recovery token; invalidates all account sessions and returns {ok:true}; user signs in again.
GET /api/profile -> {account:{id,name,email,role,tenant,active}} managed signed-in user only.
PATCH /api/profile -> {name} with session/CSRF.
POST /api/password/change -> {currentPassword,password}, current account; invalidates all sessions including current; returns {ok:true} and clears cookie.
GET /api/team -> {members:[{id,name,email,role,tenant,active}], invitations:[{id,email,role,expiresAt}]} administrator only. No credentials/hashes/tokens.
POST /api/team/invitations -> {email,role} admin+CSRF ->201 {id,token,email,role,expiresAt}; token shown once, no resend service.
DELETE /api/team/invitations/:id ->admin+CSRF {ok:true} revokes.
PATCH /api/team/:id -> {role?,active?} admin+CSRF -> safe member; reject empty patch; last-admin invariant409.
POST /api/team/:id/recovery -> {} admin+CSRF -> {token,expiresAt}; token one-time/15min, no token in audit. Generic invalid token error for accept/reset. Invites cannot replace existing account or change its role implicitly.

App route access should await asynchronous session verification without weakening gateway surface restrictions.
